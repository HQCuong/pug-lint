# Синтаксис, о котором сообщается как об `unsupported-syntax` {#syntax-reported-as-unsupported-syntax}

Парсер никогда не бросает исключений. Ввод, который он не моделирует, становится ошибкой
`unsupported-syntax` на первом смещении, которое он не может прочитать, а остаток этой строки
пропускается. Этот файл перечисляет все известные источники этой ошибки. Всё остальное, что даёт
`unsupported-syntax`, является багом.

«Недопустимый Pug» отмечает формы, которые отвергает сам Pug; они перечислены потому, что парсер
сообщает о них тем же кодом.

## Строки {#lines}

| Форма | Пример | Примечания |
| --- | --- | --- |
| Тег с интерполированным именем | `#{tag} text`, `#{tag}/` | |
| Mixin с интерполированным именем | `+#{name}()` | `+ name` (пробелы после `+`) является вызовом mixin. |
| Текстовый блок без тега | строка, состоящая только из `.`, с вложенными под ней строками текста | Pug помещает текст в родителя. Используйте строки с `\|`. |
| Интерполяция тега или mustache в начале строки | `#[b x] y`, `{{ x }}` | Используйте `\| #[b x] y` / `\| {{ x }}`. |
| Всё остальное, что не начинает конструкцию Pug | `)`, `@x`, `.5` | |
| Строки, вложенные под текст с `\|` | `\| a` с отступленным `p` под ним | Недопустимый Pug. Сообщается один раз, на первой вложенной строке; вложенные строки пропускаются и образуют область восстановления после ошибки (`doc.lines`, вид `continuation`). Строки, вложенные под литеральный HTML (`<ul>`), допустимы: Pug делает их соседними, и парсер тоже. |
| Строки, вложенные под буферизованный код | `= x` или `!= x` с отступленным `p` под ним | Недопустимый Pug. Сообщается и восстанавливается так же, как под текстом с `\|`. Под `p= x` строки являются дочерними для `p`, как в Pug. |

## После заголовка тега или вызова mixin {#after-a-tag-or-mixin-call-head}

| Форма | Пример | Примечания |
| --- | --- | --- |
| Небуферизованный код после тега | `p- x` | |
| `.`, за которой в строке есть что-то ещё | `p. text`, `p.: a` | Недопустимый Pug. |
| Текстовый блок после вызова mixin | `+m.` | |
| Раскрытие блока после вызова mixin | `+m: p` | У `MixinCall` нет поля `expansion`. В роли дочернего элемента это допустимо: `li: +m`. |
| `/` после вызова mixin | `+m/` | |
| Раскрытие блока после `/` | `img/: x` | Недопустимый Pug. |
| `:` без пробела и дочернего элемента после неё | `li:`, `li(x):b`, `when 1:` | Недопустимый Pug. |
| Дочерний элемент раскрытия, не являющийся тегом или вызовом mixin | `li: \| x`, `li: <b>x</b>`, `li: = x`, `li: // c`, `li: if x`, `when 1: each x in y` | Управляющее ключевое слово здесь никогда не читается как имя тега. |
| Тег с последующим встроенным фильтром | `p: :markdown text` | |

## Заголовки управляющих конструкций {#control-heads}

| Форма | Пример | Примечания |
| --- | --- | --- |
| Раскрытие блока после условия или цикла | `else: p`, `else : p`, `if x: p`, `unless x: p`, `else if x: p`, `while x: p`, `case x: p`, `each a in b: p`, `for a in b: p` | Недопустимый Pug. Сообщается на первом `:` заголовка вне строк и скобок, который не закрывает `?` верхнего уровня (так что `if a ? b : c` и `each v in {a: 1}` допустимы). Раскрытие работает после `when` и `default`: `when 1: p a`. |

## Фильтры {#filters}

| Форма | Пример | Примечания |
| --- | --- | --- |
| Что угодно, кроме текста, после заголовка фильтра | `:a(x):b`, `:md.x` | Вложенные фильтры читаются только как `:a:b(attrs)`, с атрибутами после последнего имени. |

## Интерполяция тега `#[…]` {#tag-interpolation}

| Форма | Пример | Примечания |
| --- | --- | --- |
| Не начинается с тега | `#[+m]`, `#[\| x]`, `#[- x]`, `#[:cdata x]` | Вызовы mixin, текст, код и фильтры внутри `#[…]` не читаются. |
| Заголовок, за которым идёт что угодно, кроме текста, кода `=`/`!=` или `: child` | `#[p.]`, `#[p- x]`, `#[img/: x]` | |

## Разбирается без ошибки, но не так, как в Pug {#parsed-without-an-error-but-not-as-pug-does}

Найдено дифференциальным оракулом (`tests/oracle`, Task 17).

| Форма | Пример | Примечания |
| --- | --- | --- |
| Комментарий после имени блока | `block content // c` | Pug заканчивает имя на `//` и делает остаток соседним комментарием, который также забирает вложенные строки. Парсер оставляет его в заголовке `block`. |
| Повторяющийся атрибут или id | `a(x=1 x=2)`, `#a#b` | Pug их отвергает; парсер принимает. |
| Пустой `else` после `each` | `each x in y` … `else` без вложенного содержимого | Pug его отвергает; парсер принимает. |
