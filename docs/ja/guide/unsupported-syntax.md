# `unsupported-syntax` として報告される構文 {#syntax-reported-as-unsupported-syntax}

パーサーは例外を投げません。モデル化していない入力は、読み取れない最初のオフセットで `unsupported-syntax` エラーになり、その行の残りは読み飛ばされます。このファイルは、このエラーが出る既知の原因をすべて挙げています。ここに載っていないものが `unsupported-syntax` を出す場合は、バグです。

「Invalid Pug」は、Pug 自体が拒否する書き方を指します。パーサーもこのコードで報告するため、載せています。

## 行 {#lines}

| 書き方 | 例 | 備考 |
| --- | --- | --- |
| 補間されたタグ名 | `#{tag} text`、`#{tag}/` | |
| 補間された mixin 名 | `+#{name}()` | `+ name`（`+` の後ろにスペース）は mixin 呼び出しです。 |
| タグのないテキストブロック | `.` だけの行と、その下にネストされたテキスト行 | Pug はテキストを親に置きます。`\|` の行を使ってください。 |
| 行頭のタグ補間またはマスタッシュ | `#[b x] y`、`{{ x }}` | `\| #[b x] y` / `\| {{ x }}` を使ってください。 |
| Pug の構文として始まらないその他のもの | `)`、`@x`、`.5` | |
| パイプで書いたテキストの下にネストされた行 | `\| a` の下にインデントされた `p` | Invalid Pug。最初のネストされた行で 1 回だけ報告されます。ネストされた行は読み飛ばされ、エラー回復の領域（`doc.lines` の種類 `continuation`）になります。リテラル HTML（`<ul>`）の下にネストされた行は有効です。Pug は兄弟として扱い、パーサーも同じです。 |
| バッファ付きコードの下にネストされた行 | `= x` または `!= x` の下にインデントされた `p` | Invalid Pug。報告と回復はパイプで書いたテキストの下の場合と同じです。`p= x` の下の行は、Pug と同じく `p` の子です。 |

## タグまたは mixin 呼び出しのヘッドの後 {#after-a-tag-or-mixin-call-head}

| 書き方 | 例 | 備考 |
| --- | --- | --- |
| タグの後のバッファなしコード | `p- x` | |
| `.` の後に同じ行で続きがある | `p. text`、`p.: a` | Invalid Pug。 |
| mixin 呼び出しの後のテキストブロック | `+m.` | |
| mixin 呼び出しの後のブロック展開 | `+m: p` | `MixinCall` には `expansion` フィールドがありません。子としてなら問題ありません: `li: +m`。 |
| mixin 呼び出しの後の `/` | `+m/` | |
| `/` の後のブロック展開 | `img/: x` | Invalid Pug。 |
| `:` の後にスペースと子が続かない | `li:`、`li(x):b`、`when 1:` | Invalid Pug。 |
| タグまたは mixin 呼び出しではない展開の子 | `li: \| x`、`li: <b>x</b>`、`li: = x`、`li: // c`、`li: if x`、`when 1: each x in y` | ここでは、制御構文のキーワードがタグ名として読まれることはありません。 |
| インラインフィルターが続くタグ | `p: :markdown text` | |

## 制御構文のヘッド {#control-heads}

| 書き方 | 例 | 備考 |
| --- | --- | --- |
| 条件分岐またはループの後のブロック展開 | `else: p`、`else : p`、`if x: p`、`unless x: p`、`else if x: p`、`while x: p`、`case x: p`、`each a in b: p`、`for a in b: p` | Invalid Pug。ヘッドの中で、文字列と括弧の外にあり、最上位の `?` を閉じない最初の `:` で報告されます（そのため `if a ? b : c` や `each v in {a: 1}` は問題ありません）。展開は `when` と `default` の後では使えます: `when 1: p a`。 |

## フィルター {#filters}

| 書き方 | 例 | 備考 |
| --- | --- | --- |
| フィルターのヘッドの後にテキスト以外が続く | `:a(x):b`、`:md.x` | ネストされたフィルターは `:a:b(attrs)` の形でのみ読まれ、属性は最後の名前の後に置きます。 |

## タグ補間 `#[…]` {#tag-interpolation}

| 書き方 | 例 | 備考 |
| --- | --- | --- |
| タグで始まらない | `#[+m]`、`#[\| x]`、`#[- x]`、`#[:cdata x]` | mixin 呼び出し、テキスト、コード、フィルターは `#[…]` の中では読まれません。 |
| ヘッドの後に、テキスト、`=`/`!=` コード、`: child` 以外が続く | `#[p.]`、`#[p- x]`、`#[img/: x]` | |

## エラーなしでパースされるが、Pug とは異なるもの {#parsed-without-an-error-but-not-as-pug-does}

差分オラクル（`tests/oracle`、Task 17）で見つかったものです。

| 書き方 | 例 | 備考 |
| --- | --- | --- |
| block 名の後のコメント | `block content // c` | Pug は名前を `//` で終え、残りを、ネストされた行も取り込む兄弟のコメントにします。パーサーはそれを `block` のヘッドに含めます。 |
| 属性または id の重複 | `a(x=1 x=2)`、`#a#b` | Pug は拒否しますが、パーサーは受け入れます。 |
| `each` の後の空の `else` | `each x in y` … 中身のない `else` | Pug は拒否しますが、パーサーは受け入れます。 |
