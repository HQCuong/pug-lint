# 既知の制限

- **複数行の属性値にはバッククォートが必要です。** `'…'` や `"…"` の値の中の改行は Pug の構文エラーです（Pug 自体もコンパイルしません）。`vue/no-parsing-error` が報告します。テンプレートにパースエラーがある間は、その中で fix は一切適用されません。
- **省略記法は `vue/*` rule からは属性として見えません。** `.class` や `#id` の省略記法は属性として公開されないため、`vue/no-restricted-class` のような rule は省略記法で書かれたクラスを検出できません。
- **Vue AST は HTML テンプレートのものと数か所で異なり**、`vue/*` rule がそれに気づくことがあります。パイプで書いたテキストの各行（`| text`）はそれぞれ独立したテキストノードになります。テンプレートの直下にあるテキストにはテキストノードがありません。文字列の属性値は加工されずに渡されるため、ディレクティブの文字列の中のエスケープされたクォート（`:x="f(\"a\")"`）は、誤った Vue のパースエラーを引き起こすことがあります。
- **クォートなしの属性値と `${}` の属性値**（`a(href=url)`、``a(title=`${x}`)``）は、Vue のバインディングではなく、Pug のコンパイル時の式です。`vue/*` rule には単なる属性値として渡され、それらを書き換える fix は fix ガードがすべて破棄します。
- **クォートで始まる値は、1 つの文字列でなければなりません。** `a(title="x" + y)` は Pug としては有効ですが、仕様としてパースエラー（`vue/no-parsing-error`）になります。`a(title=("x" + y))` または `a(:title="'x' + y")` と書いてください。
- **単独の CR による改行。** 行末が単独の `\r`（旧 Mac 形式）のテンプレートでは、`vue-pug/*` rule は問題を報告しますが fix はせず、トークナイザーはパースエラーを報告します。ファイルを LF または CRLF に変換してください。
- **一部の Pug 構文は、パーサーが未対応として報告するか、Pug とは異なる解釈でパースします。** [未対応の Pug 構文](./unsupported-syntax)を参照してください。
- **fix ガードのコストと一部だけの fix セット:** [fix ガード](./fix-guard#cost)を参照してください。
